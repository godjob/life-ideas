# 制限言語（ASD-STE100）によるLLM出力最適化と可視化プロンプト手法

## 概要

元Tesla AIのAndrej Karpathy氏が提唱するように、LLM（大規模言語モデル）の利活用フェーズは「モデルへの命令設計」から「出力結果の効率的な理解・評価」へとシフトしています。本ページでは、航空宇宙・防衛分野の制限言語仕様「ASD-STE100」をプロンプトに組み込むことでLLMの冗長さを排除し、さらにHTMLやコード可視化を組み合わせることで人間の認知負荷を劇的に削減する出力最適化手法について解説します。

## 主要な知見

- **制限言語（ASD-STE100）によるテキスト最適化**: 語彙数や文法構造が厳密に制限されたASD-STE100（Simplified Technical English）を出力フォーマットとして指示することにより、曖昧さや冗長な説明を排除した極めてクリアなドキュメント・マニュアルを生成できます。
- **可視化コード出力による理解の加速**: テキストのみの要約にとどまらず、HTML、CSS、SVG、または動画生成コードなどを直接出力させることで、複雑なシステム仕様や動的な処理フローをひと目で視覚的に理解できるようになります。
- **人間側の役割シフト（「実行」から「監督・評価」へ）**: AIが業務を自動実行する領域が増加する中で、人間のコアスキルは作業そのものから[Agentic Engineeringの監督者モデル：直接実行から検証・調整へのシフト](agentic-engineering-supervisor-model.md)へと移行します。いかに高速にモデルの出力を検品・評価できるかが生産性を左右します。
- **プロンプト最適化によるトークン・コスト削減**: 制限言語の適用は文脈の簡潔化をもたらすため、[プロンプト最適化によるコスト効率化：Cavemanテクニックとトークン削減戦略](prompt-optimization-cost-efficiency.md)と同様に、コンテキスト窓の節約と推論コストの抑制にも直接寄与します。

## ASD-STE100と可視化プロンプトの活用構造

LLMの出力を人間が「一瞬で把握する」ためのパイプラインは以下のように整理できます。

```
[複雑なシステム仕様・長文ログ]
       │
       ▼
┌──────────────────────────────────────────┐
│ LLM (プロンプト指示)                     │
│  1. ASD-STE100規約の適用 (簡潔・一義化)  │
│  2. インタラクティブHTML/SVG出力指示     │
└──────────────────────────────────────────┘
       │
       ▼
┌──────────────────────────────────────────┐
│ 人間（監督者・判定者）                    │
│  ・冗長な文章を読む必要がない            │
│  ・ブラウザ上で動的図解を確認・迅速評価  │
└──────────────────────────────────────────┘
```

### 1. ASD-STE100（Simplified Technical English）の適用
ASD-STE100は、英語の語彙を制限し（1つの語に1つの意味）、1文の長さを15〜20語以内に抑え、受動態を避けて能動態を使用するルール群です。これをLLMのシステムプロンプトに指定することで、ハルシネーションの混入や回りくどい表現を防ぎ、[ドキュメント形式変換とMarkdown標準化：複数形式資料の統一化によるAI分析効率向上](document-format-conversion-markdown-standardization.md)と同様の情報の解像度向上効果が得られます。

### 2. 可視化形式の併用
システム構造やトラブルシューティング手順を出力させる際、単なるMarkdown文章ではなく、1つのファイルで完結するHTML/JavaScriptコードを出力させます。これをブラウザで開くことで、可視化されたノード図やステップ別のシミュレーションが可能になり、[データ統合可視化技術の製造業応用：バラバラなデータを統一的マップへ変換](data-integration-visualization-manufacturing-application.md)のような高度な情報共有を即座に実現できます。

### 3. AI時代の監督者マインドセット
指示を出し、出てきた膨大なテキストを人間が苦労して解読していては本末転倒です。[AIマインドセット：人間は思考、AIは実行の役割分担モデル](ai-mindset-human-thought-ai-execution.md)に基づき、「AI側に出力フォーマットを工夫させて人間の認知負荷を下げる」こと自体が、高度な[指示設計の3要素フレームワーク：背景・目的・期待アウトプット形式](instruction-design-three-elements.md)の実践と言えます。

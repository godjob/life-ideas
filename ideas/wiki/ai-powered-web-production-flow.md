# AI時代のWeb制作フロー：コーディング先行による設計→実装→デザイン体制

## 概要

従来の「設計→デザイン→コーディング」というWeb制作フローが逆転する新しい時代が到来している。AIの活用により、設計後すぐにコーディングを実行し、早期モックを生成してからデザインを行うことで、手戻りを激減させ、制作効率を飛躍的に高める方法論である。これにより、プログラミング経験のない非エンジニアでもアイデアがあれば即座に実装・プロトタイピングが可能な環境が整備された。

さらに最近では、会話的なノリや直感的なアイデアを即座にコード化・試作する「バイブコーディング」という手法も台頭しており、ゲーム開発やWebサービス開発における制作速度とアプローチを根本から変えつつある。

## 主要な知見

- **AIツールの役割分担が重要**: [Claude ChatとClaude Codeの役割分担：効率的なワークフロー設計](claude-chat-claude-code-workflow.md)のように、Claude（チャット）は「相談・設計・プロンプト生成」、Claude Codeは「実行・ファイル操作」という明確な役割分担が最も効率的なワークフローを実現する

- **Web制作フローの逆転とバイブコーディング**: 従来の「設計→デザイン→コーディング」から「設計・直感（アイデア）→コーディング（AI）→デザイン・UX調整（人間）」へシフト。AIが圧倒的な物量処理や初期実装を担当することで、直感的なアイデア（バイブス）から即座に動作するプロトタイプを生み出せる

- **手戻りの大幅削減**: 完成度の低いデザイン段階での指摘より、動作するモックを見てから修正する方が全体的な変更コストが低い。ステークホルダーも「見える」「動く」ものに対してより正確なフィードバックを提供できる

- **非エンジニア・アイデア主導の開発**: タレントマネジメントシステムや匿名褒めアプリ、個人制作のWebサービスやゲームなど、専門的なエンジニアリング知識がない者でも、[プログラミング経験なしのAIによるシステム構築](ai-assisted-system-building-non-programmers.md)が現実のものとなっている

- **プロトタイピング優先と人間中心のUX調整**: [速さが命題：検討より先にプロトタイプを出す姿勢](speed-first-prototyping.md)を前提としつつ、最終的な価値向上にはデータ上の正確さだけでなく「人間の体感（UX）」に合わせた細かな違和感の調整や感性の反映が不可欠である

## Web制作フロー：従来型 vs AI型

### 従来の制作フロー
1. **要件定義・設計** → 2. **デザイン** → 3. **コーディング** → 4. **テスト・調整**

問題点：
- デザイン段階での修正が後工程に影響
- ステークホルダーが「完成度の低いデザイン」では正確なフィードバックができない
- コーディング段階での技術的課題が後から浮上
- 全体的に時間とコストがかかる

### AI時代の新しいフロー
1. **要件定義・アイデア発案** → 2. **コーディング（AI実装・バイブコーディング）** → 3. **モックデプロイ・動作確認** → 4. **デザイン・人間感性の適用（人間）** → 5. **体感（UX）調整・最終最適化**

メリット：
- 早期段階で**動作するシステム・プロトタイプ**が存在
- ステークホルダーが実際に触って判断できるためフィードバック精度が向上
- デザイン修正や機能調整は動くWebサイト/アプリ上で確認しながら行える
- 大量処理や自動化（投稿審査やデータ生成など）をAIに任せることで、人間はクオリティコントロールや体験価値に集中できる
- 総工期が短縮される

## 実装・制作のポイント

### 設計・バイブス発案フェーズ
- ユーザー要件とコアとなる体験アイデアを整理
- データベーススキーマの基本構造やAPIエンドポイントの決定
- 詳細なビジュアルデザインはあらかじめ決め込まず、アイデアのプロトタイプ化を優先する

### AIコーディング（バイブコーディング）フェーズ
- 設計書や会話プロンプトをベースに、[Claude Code設定駆動ワークフロー：CLAUDE.mdの設計規約自動遵守と保守業務の並列化](claude-code-configuration-driven-workflow.md)などを活用して実装を実行
- フロントエンドとバックエンドを並行して高速実装
- 動作確認可能なプロトタイプを速やかに構築し、認証やデータ保存などの基本機能やエラーハンドリングを盛り込む

### モック・デプロイと自動化設計
- ステークホルダーやユーザーが実際に操作できる開発・ステージング環境へデプロイ
- AIによる大量処理や自動審査・監視などのバックグラウンド機能を組み込み、運用の省力化を図る

### デザイン・感性適用フェーズ
- 動作するシステムを見ながらUIデザインやビジュアルの統一を適用
- あえて制約を設けるアプローチ（レトロ風のデザインや仕様制約など）を取り入れることで、「AIっぽさ」を消して独特の「味」やブランディング価値を創出する
- レスポンシブ対応や視認性・操作感の改善

### 体感（UX）微調整・最終調整フェーズ
- **人間の体感に合わせた感覚調整**: 単なる数値データ上の正確さだけでなく、実際に人間が操作したときの「心地よさ」「手応え」「違和感の有無」といった感性領域の調整を徹底的に行う
- [製造業のAI即日適用パターン：資料処理と修正要望の自動化](manufacturing-ai-quick-wins.md)のような自動化ツールの組み込みやパフォーマンス最適化、セキュリティ監査を経て本番デプロイ

## AIツール選定と活用パターン

### Claude（チャット版）の活用場面
- システム全体の設計相談、技術選定
- プロンプトの最適化や対話を通じたアイデアのブレインストーミング

### Claude Code / エージェントの活用場面
- 実際のコード生成・リファクタリング・ファイル操作
- 大量のデータ処理や審査プロセスの自動化ロジック構築

### あえて制約をかける設計アプローチ
AI時代において均質化しやすいプロダクトの中で、あえてレトロゲームのような制約や枠組みを意図的に設けることで、AI特有の無機質さを抑え、クリエイター独自の視点やストーリー性を引き出す手法が有効となる。

## 事例に見るメリット

### バイブコーディングによるゲーム・サービス開発の事例
- アイデア脳を持つクリエイターがAIを用いてプロトタイプを即座に構築。圧倒的なコード生成力により、少人数・短期間で独創的なゲームやWebサービスを形にする
- データ的な整合性だけでなく、実際にプレイ・操作した際の「人間の体感」に基づく微調整を繰り返すことで、完成度の高い体験を提供

### タレントマネジメントシステムの事例
- 企業内人材管理の要件を設計 → AIで実装 → 動作するモックでステークホルダーフィードバック取得 → 実際の業務フローに合わせた調整
- ~~従来であれば要件定義に3週間、デザインに2週間かかっていた~~ → [システム開発速度の劇的加速：数週間から1日への実装期間短縮と現場課題解決の民主化](system-development-velocity-acceleration-ai-tools.md)により、AI活用で要件定義〜モック生成が数日〜1週間程度に大幅短縮

### 匿名褒めアプリの事例
- チーム内コミュニケーション向上を目標に設計 → AIで実装 → ユーザーが実際に使い体験 → 使いやすさに基づくUI改善
- 要望の言語化が格段に容易になり、修正ループが高速化

## 注意点と課題

- **品質保証とセキュリティ**: AI生成コードの検証が必須。[非エンジニア向けAIセキュリティガバナンス：分ける・残す・防ぐ3原則と権限管理の実装](ai-security-non-engineer-governance-framework.md)に留意し、セキュリティやデータ整合性を確保する
- **人間中心の感覚調整の必要性**: AIは仕様通りのロジックを組むことは得意だが、「触っていて気持ちいいか」「直感的に伝わるか」というUXの最終調整は人間が主導する必要がある
- **プロンプト設計と意図の明確化**: 曖昧な指定ではAIが意図と異なる実装をするため、文脈や要件の伝達が重要となる
- **エンジニア・クリエイターの役割変化**: コードを書く作業から、AIに指示を出し、出来上がったプロダクトの味付けやUX・ガバナンスを監督する役割へのシフトが進む

> 正解ではない場合もあったり、その手順にも再現性がありません。つまり間違える前提でAI開発と付き合う必要があり、そのストレスやLLMとの不毛に見えるやり取りをいかに低減できるかが、開発体験に直結します。 　2つ目のストレスは「待ち時間が発生する」ということです。 　いかにAIが高速に、これまでの人間の作業の10倍の速度で動こうとも、AIの処理を待つ時間が発生します。AIの性能も上がっていますが、より複雑で高度なことを行う開発では当然の出来事です。しかし、処理を行ったり何かLLMに質問したりする度に、開発の手が止まることはあまり気持ちの良いことではありません。 　筆者は、これらのAI支援開発現場における新たな2つのストレスを、Claude CodeがCLIを採用したことで低減し、開発体験を向上させたために、ここまで一気に普及したのではないかと考えています。

> 5.4 　 Claude Codeの今後の展望 　2025年5月末にリリースされたClaude CodeはCLIベースの環境を選ばないAIコーディングエージェントとして瞬く間にエンジニアに受け入れられ、わずか数ヶ月で11万5千人の開発者が利用し、週間1億9500万行のコードを処理するまでに成長しました。 　Claude CodeがAnthropic社内で産声を上げた際、Anthropicの競争力確保のために「Claude Codeを世の中に公開しないほうが良いのではないか」という議論にすらなったそうです。社内でリリースした際のエンジニアへの広がりと生産性の拡大を目にして、それほど力を持ったツールだという確信があったようです。 　そのような意見もありながら公益法人でもあるAnthropicは、モデルをユーザーに安全に使ってもらうことが彼らのコアだと位置付けており、Claude Codeが多くの人々に使われることで、安全にモデルを使用する方法をサービス提供者として学ぶことができるだろうと考えたそうです。 　結果的に、CLIによるコード生成が一つのジャンルとして認知され、多くのフォロワーを生み出しました。 　OpenAIのCodex、GoogleのGemini CLI、AlibabaのQwen Code CLIといったオープンソースのCLIツールも次々と登場しており、これらはすべてClaude Codeが切り開いたやり方を踏襲していると言っても過言ではありません。
